# SX127x Radio Driver

## Overview

This project uses the Semtech SX1276 / SX1278 LoRa transceiver as the radio communication device.

The SX127x is responsible for:

* radio transmission
* radio reception
* FIFO management
* LoRa modulation
* IRQ signaling
* packet timing
* RF frequency generation

The STM32 does not transmit LoRa packets directly.

It configures the SX127x over SPI, and the radio performs the RF communication.

This document explains how the driver controls the transceiver and why specific design decisions were made.

---

## Driver Responsibility

```text id="sx1"
drivers/sx127x/
```

Responsible for:

* register read/write
* LoRa mode enable
* frequency configuration
* TX mode
* RX mode
* FIFO handling
* IRQ flag management
* packet transmission
* packet reception

The application must never manipulate radio registers directly.

Only the driver layer should own radio control.

---

## Basic Communication Model

The communication path is:

```text id="sx2"
STM32
↓
SPI
↓
SX127x registers
↓
internal FIFO
↓
RF transmission
```

The MCU sends commands.

The SX127x performs the radio work.

This separation is fundamental.

---

## Operating Modes

The SX127x uses multiple operating modes.

The most important ones are:

```text id="sx3"
Sleep
Standby
TX
RX Continuous
```

Each mode has a specific purpose.

---

## Sleep Mode

Used for:

* startup
* LoRa mode enable
* lowest power state

Example:

```c id="sx4"
sx127x_set_sleep_mode();
```

This is required because the LoRa bit must be configured while the radio is in Sleep mode.

This is defined by the datasheet.

It is not optional.

---

## LoRa Mode Enable

The SX127x supports both:

* FSK/OOK
* LoRa modulation

This project uses:

```text id="sx5"
LoRa mode
```

which is enabled by:

```c id="sx6"
sx127x_set_lora_mode();
```

The radio must first enter Sleep mode.

Then LoRa mode is enabled.

Only after that can normal LoRa operation begin.

---

## Standby Mode

Used for:

* safe register configuration
* FIFO preparation
* transition before TX/RX

Example:

```text id="sx7"
Sleep
↓
LoRa enable
↓
Standby
```

The radio should not jump directly from initialization to transmission.

Standby provides a stable transition state.

---

## TX Mode

Used for:

```text id="sx8"
packet transmission
```

Flow:

```text id="sx9"
write FIFO
↓
set payload length
↓
clear IRQ flags
↓
enter TX mode
↓
wait TX_DONE
```

Example:

```c id="sx10"
sx127x_send_packet(...)
```

Only after `TX_DONE` is the packet considered physically transmitted.

This is important for reliable communication.

---

## RX Continuous Mode

Used for:

```text id="sx11"
continuous listening
```

The receiver remains waiting for packets.

Example:

```c id="sx12"
sx127x_start_receive();
```

This is ideal for:

* ACK reception
* Ping/Pong response
* real-time packet handling

The RX node should remain in continuous RX mode whenever possible.

---

## Frequency Configuration

This project uses:

```text id="sx13"
915 MHz
```

configured at:

```text id="sx14"
include/drivers/sx127x/sx127x_config.h
```

Example:

```c id="sx15"
#define SX127X_FREQUENCY_HZ 915000000UL
```

The frequency is converted into:

```text id="sx16"
FRF register values
```

using the crystal frequency and internal scaling.

This avoids hardcoded magic values.

The function is:

```c id="sx17"
sx127x_set_frequency(...)
```

which is reusable for other frequencies.

---

## FIFO Usage

The SX127x uses an internal FIFO buffer.

The MCU does not directly transmit payload bytes over RF.

Instead:

```text id="sx18"
payload
↓
FIFO
↓
radio transmission
```

This is true for both TX and RX.

---

## TX FIFO Flow

Transmission uses:

```text id="sx19"
FIFO_TX_BASE_ADDR
FIFO_ADDR_PTR
PAYLOAD_LENGTH
```

Flow:

```text id="sx20"
set TX base
↓
set FIFO pointer
↓
write payload bytes
↓
set payload length
↓
enter TX mode
```

This ensures deterministic packet transmission.

---

## RX FIFO Flow

Reception is more sensitive.

The correct flow uses:

```text id="sx21"
FIFO_RX_CURRENT_ADDR
```

and not always:

```text id="sx22"
0x00
```

This is critical.

---

## Why `FIFO_RX_CURRENT_ADDR` Matters

A common mistake is:

```c id="sx23"
FIFO_ADDR_PTR = 0x00
```

for every received packet.

This is unreliable.

The radio stores the actual packet start address in:

```text id="sx24"
FIFO_RX_CURRENT_ADDR
```

The correct flow is:

```text id="sx25"
RX_DONE
↓
read RX_NB_BYTES
↓
read FIFO_RX_CURRENT_ADDR
↓
set FIFO_ADDR_PTR
↓
read FIFO
```

Without this, packet reception becomes unstable.

This was one of the most important fixes in the project.

---

## IRQ Flags

The SX127x uses internal IRQ flags for radio events.

Important examples:

```text id="sx26"
TX_DONE
RX_DONE
CRC_ERROR
```

These flags are used for:

* TX completion
* RX completion
* packet validation

Example:

```text id="sx27"
TX waits for TX_DONE
```

and:

```text id="sx28"
RX validates RX_DONE
```

before reading FIFO.

---

## Why ACK Works

ACK depends on reliable TX/RX state transitions.

Flow:

```text id="sx29"
TX sends DATA
↓
wait TX_DONE
↓
enter RX mode
↓
wait ACK
```

If TX returns too early, ACK may be lost.

If RX is not restarted correctly, delivery confirmation fails.

Reliable communication depends on correct radio state control.

This is why driver correctness matters.

---

## Why RX Must Restart

After packet processing:

```text id="sx30"
RX must return to receive mode
```

Example:

```c id="sx31"
sx127x_start_receive();
```

Without this:

```text id="sx32"
the receiver stops listening
```

and future packets are lost.

This is mandatory after:

* DATA reception
* ACK transmission
* PONG transmission

---

## Polling vs Interrupts

This project uses:

```text id="sx33"
polling
```

instead of:

```text id="sx34"
DIO0 interrupts
```

Example:

```text id="sx35"
check IRQ flags repeatedly
```

This was intentional.

Reasons:

* easier debugging
* simpler validation
* deterministic bring-up
* reduced initial complexity

This is the correct first architecture.


---

## Design Goal

The objective is not only:

```text id="sx36"
make the radio transmit
```

The real goal is:

```text id="sx37"
build a reusable and maintainable SX127x radio driver
```

that can support future embedded communication systems.
